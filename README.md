# Jarvis — локальный ИИ-ассистент для Windows

> **Статус:** проектирование (v0.1). Код ещё не начат — в репозитории лежит проектный пакет:
> архитектура, дорожная карта, аудит существующих наработок и открытые вопросы.

## 1. Цель

Персональный ассистент уровня «Джарвис»:

- понимает текст и голос, отвечает голосом и в интерфейсе;
- выполняет задачи на ПК: файлы, команды, программы, браузер, документы;
- пишет и запускает код в песочнице;
- генерирует изображения (видео — экспериментально/через облако);
- помнит контекст, проекты, предпочтения и историю задач;
- **не занимает всю видеопамять**: тяжёлые модели загружаются послойно, по одной, и выгружаются после задачи;
- работает локально; облако — только опционально и по явному разрешению.

### Что уже загружено в VRAM

На момент замера: **5,8 ГБ из 8 ГБ** занято рабочим столом, Chrome, Telegram, NVIDIA Broadcast и запущенным `llama-server` Ollama.
Свободно ~1,8 ГБ — этого не хватит даже на 8B-модель.

**Вывод:** ассистент обязан считать бюджет по *фактически свободной* VRAM, а не по паспортным 8 ГБ,
и уметь выгружать чужие/свои модели. Для тяжёлых задач браузер и Broadcast придётся закрывать или мириться с меньшими моделями.

## 3. Ключевая идея — «послойное развёртывание»

Термин раскрывается на четырёх уровнях (подробно — в `docs/ARCHITECTURE.md`):

1. **Сервисная послойность** — ядро и wake-word всегда живы; тяжёлые воркеры (LLM, SDXL, видео) запускаются по требованию.
2. **Модельная послойность** — tiers 0–4: роутер 4B → чат 8B → кодер 7B → ASR/TTS/эмбеддинги → SDXL/видео. Одновременно живёт только то, что помещается.
3. **Тензорная послойность** — квантизация GGUF, частичный offload слоёв на GPU (`-ngl`), квантование KV-кэша.
4. **Конвейерная послойность** — этапы медиа-пайплайна идут последовательно: выгрузили LLM → загрузили SDXL → сгенерировали → выгрузили.

## 5. Принципы

1. **Local-first.** Базовые функции работают без интернета. Облако — явное исключение, а не зависимость.
2. **Одна тяжёлая модель за раз.** Никаких «пусть Ollama сама разберётся»: только leases, бюджеты и очередь.
3. **Безопасность по умолчанию.** Ядро — без прав администратора; записи — только в workspace; опасное — с подтверждением.
4. **Всё логируется.** Каждый шаг, инструмент, модель и подтверждение — в аудит.
5. **Обратимость.** Удаление — в корзину, перезапись — с бэкапом, код — в git, система — с точкой восстановления.
6. **Модульность.** Инструмент = типизированный контракт + права + риск. Новые возможности не трогают ядро.
7. **Наблюдаемость.** Латентность, VRAM, токены/с, OOM, стоимость — на дашборде.
8. **Сначала вертикальный срез.** Один сценарий от голоса до результата, потом расширение.

## 6. Границы v1

**Входит:** текст/голос, файлы, безопасный shell, поиск по документам, память, генерация изображений, браузер, запуск кода в песочнице, web-UI, аудит.

**Не входит:** полная автономия без подтверждений, управление играми, мобильное приложение, мультипользовательский режим, локальное видео в высоком качестве, самопереписывание политики безопасности.
