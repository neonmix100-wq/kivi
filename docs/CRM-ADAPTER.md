# AltCRM adapter: CDP, fill-only policy

Адаптер AltCRM — тонкий слой Playwright/CDP поверх уже открытого и
авторизованного Chrome. Он **читает** карточку заказа, **заполняет** поля
чек-листа, комментарий, строки акта и окно задачи, но никогда не сохраняет,
не отправляет, не удаляет, не оплачивает и не создаёт задачу. Сохранение
всегда делает человек.

Код:

- [`src/kivi/modules/work_crm/altcrm.py`](../src/kivi/modules/work_crm/altcrm.py) —
  соединение, селекторы, `read_order`, `fill_order`, `add_work_rows`,
  `create_task`, `_click_safe`;
- [`src/kivi/modules/work_crm/tools.py`](../src/kivi/modules/work_crm/tools.py) —
  `crm.read`, `crm.fill`, `crm.act`, `crm.task` и `compose_draft`;
- [`tests/unit/test_altcrm.py`](../tests/unit/test_altcrm.py) — 34 теста на
  fake-странице;
- [`tests/unit/test_crm_tools.py`](../tests/unit/test_crm_tools.py) — 29 тестов
  на реальном `ToolExecutor` и fake-клиенте.

Домен и черновики без браузера описаны отдельно в
[`CRM-DOMAIN.md`](CRM-DOMAIN.md). Этот документ — только про автоматизацию
страницы и политику «заполнить, но не сохранить».

## 1. Запуск Chrome для CDP

Агент подключается к **уже запущенному** браузеру. Он не запускает Chrome,
не создаёт профиль, не хранит пароли и не читает cookies.

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 `
  --user-data-dir="C:\chrome-agent"
```

1. Используйте **отдельный** `--user-data-dir`. Начиная с Chrome 136
   remote debugging не включается для профиля по умолчанию — это требование
   безопасности самого Chrome, а не Kivi.
2. Войдите в AltCRM в этом окне один раз. Пароль вводит человек; Kivi его не
   видит и не хранит.
3. Откройте карточку заказа, например
   `https://<crm>/devices/order/<id>`. Вкладка должна оставаться открытой.
4. Проверьте, что порт отвечает:

   ```powershell
   Invoke-RestMethod http://127.0.0.1:9222/json/version
   ```

5. Не запускайте второй Chrome с тем же `--user-data-dir`: порт займёт первый
   процесс, а вкладки окажутся не там, где ожидает адаптер.

Настройка по умолчанию:

```python
from kivi.modules.work_crm.altcrm import AltCrmClient, AltCrmConfig

client = AltCrmClient(
    AltCrmConfig(
        cdp_url="http://127.0.0.1:9222",
        order_url_contains="altcrm",   # подстрока URL карточки заказа
        timeout_ms=15000,
    )
)
```

`order_url_contains` сравнивается без учёта регистра. Пустая строка означает
«любая вкладка» и полезна только для отладки: в работе всегда указывайте
фрагмент URL заказа. Адаптер выбирает **последнюю** подходящую вкладку и
никогда не создаёт новую.

Соединение ленивое: `sync_playwright().start()` и
`chromium.connect_over_cdp(...)` вызываются при первом действии. `close()`
идемпотентен, отключает Playwright, но **не закрывает** Chrome и не закрывает
вкладку пользователя. Для тестов есть `page=` (готовая fake-страница) и
`playwright_factory=` (fake-менеджер).

## 2. Селекторы

Значения по умолчанию перенесены из старого `selectors.toml`. Их можно
переопределить через `AltCrmConfig(selectors={...})`; вложенные словари
сливаются с дефолтами, а `resolve_selectors` проверяет обязательные ключи и
компилирует `title_regex`.

| Секция | Ключ | По умолчанию | Где используется |
|---|---|---|---|
| `order` | `title_regex` | `Устройство\s*#(\d+)` | номер устройства в тексте карточки |
| `order` | `edit_button` | `Редактировать` | вход в режим правки |
| `order` | `add_task_button` | `Добавить задачу` | открыть окно задачи |
| `comment` | `placeholder` | `Напишите сообщение...` | комментарий в чат заказа |
| `checklist` | 4 канонические подписи | совпадают с подписями | ключ — подпись поля, значение — его placeholder |
| `task` | `dialog_title` | `Добавление новой задачи` | найти окно задачи |
| `task` | `create_button` | `Создать задачу` | только для поиска границ окна; **не нажимается** |
| `task` | `comment_placeholder` | `Комментарий` | запасной селектор комментария |
| `task` | `due_placeholder` | `Срок выполнения` | поле срока |
| `act` | `block_title` | `Расчет стоимости запчастей` | найти блок акта |
| `act` | `search_placeholder` | `Поиск` | поле поиска работы |
| `act` | `add_button_class` | `add-form-btn` | кнопка «+» |
| `act` | `name_class` | `name_input` | название работы |
| `act` | `row_class` | `table-row` | строка таблицы |
| `act` | `warranty_class` | `warranty-input` | гарантия, дни |
| `act` | `price_class` | `price-input` | цена, руб. |

Ключи `checklist` — закрытый набор
[`CHECKLIST_LABELS`](../src/kivi/modules/work_crm/altcrm.py): подписи полей
могут меняться только вместе с `drafts.build_checklist`. Значения словаря — это
placeholder конкретной CRM, поэтому при дрейфе вёрстки достаточно поменять
значение, не трогая ключ.

Все селекторы — текстовые (`get_by_text`, `get_by_placeholder`,
`get_by_label`) или CSS-классы. Адаптер не выполняет `page.evaluate` и не
принимает JavaScript/XPath/селекторы от модели. XPath используется только
внутри адаптера для поиска предка блока акта и окна задачи — это фиксированная
строка, а не пользовательский ввод.

## 3. Действия

Все методы возвращают список
[`FieldResult`](../src/kivi/modules/work_crm/altcrm.py) (`field`, `ok`,
`error`, `note`, `strategy`). Ошибка поля — значение, а не исключение; ошибка
соединения или страницы — `AltCrmError` (наследник `ToolError`).

### `read_order() -> OrderInfo`

- берёт `inner_text("body")`, сжимает пустые строки, ограничивает 6000
  символами;
- `device_id` — из `title_regex`, `order_code` — из пути `/device/<id>`;
- `fields` — строки вида `Подпись: значение` (до 40 полей, значение до 300
  символов);
- не нажимает и не заполняет ничего.

### `fill_order(comment, checklist) -> list[FieldResult]`

1. Проверяет длину комментария (≤ 5000) и меток (значения ≤ 2000).
2. Неизвестная метка → `ok=False`, без действий на странице.
3. Если есть что заполнять, нажимает **видимую** «Редактировать» через
   `_click_safe`. Если кнопки нет — считает, что режим правки уже включён.
4. Для каждого поля пробует exact placeholder → contains placeholder →
   `get_by_label` → CSS `input/textarea[placeholder=...]`. Требует ровно один
   видимый и доступный элемент; иначе возвращает понятную ошибку.
5. После `fill` сверяет `input_value()` с ожидаемым значением. Несовпадение —
   ошибка «значение не принято полем», а не молчаливый успех.
6. Комментарий заполняется отдельно и получает `note="не отправлено"`.

`Сохранить` не нажимается ни при каком результате.

### `add_work_rows(rows) -> list[FieldResult]`

Строки принимают `name`, `price`/`price_rub`, `warranty`/`warranty_days`
(1..20 строк, имя ≤ 200). Для каждой работы:

1. находит блок «Расчет стоимости запчастей» и поле поиска;
2. пропускает работу, уже стоящую в блоке (по названию);
3. вводит название, нажимает «+» (не через `_click_safe`, но это не
   сохраняющая кнопка), ждёт появления строки;
4. проверяет, что в новой строке ровно по одному полю гарантии и цены;
5. заполняет гарантию и, если цена > 0, цену; нулевая цена остаётся
   человеку (`note="цена не указана — введите вручную"`).

Если структура строки не совпала с ожидаемой, адаптер останавливается на этой
работе и пишет ошибку, а не заполняет случайные поля. Сохранения нет.

### `create_task(comment, when_text="") -> list[FieldResult]`

1. Нажимает «Добавить задачу» (безопасная кнопка).
2. Ждёт заголовок «Добавление новой задачи» и определяет границы окна по
   кнопке «Создать задачу» (кнопка используется только как якорь).
3. Срок: пустая строка — оставить срок CRM; `ДД.ММ.ГГГГ[ ЧЧ:ММ]`,
   `ГГГГ-ММ-ДД[ ЧЧ:ММ]`, «завтра», «послезавтра», «через N дней/часов/минут»
   разбираются локально; непонятная фраза → `ok=False` и просьба поставить
   срок вручную.
4. Заполняет комментарий и возвращает
   `FieldResult("создание задачи", ok=True, note="не нажато: нажмите «Создать
   задачу» вручную")`.

Кнопка «Создать задачу» не нажимается никогда — даже если селектор
`create_button` указывает на неё.

## 4. Инвариант «не сохранять»

Единственная точка кликов —
[`_click_safe(text)`](../src/kivi/modules/work_crm/altcrm.py). Текст
нормализуется в нижний регистр, и если он содержит любой маркер из
`NEVER_CLICK_MARKERS`, выбрасывается `AltCrmError`:

- `сохранить`
- `отправить`
- `удалить`
- `оплатить`
- `скидка`
- `создать` (включая «Создать задачу»)

Это работает и для селектора из конфига: если `edit_button` ошибочно указать
как «Сохранить», клик будет отклонён, а не выполнен. Проверка идёт до любых
действий на странице.

Следствия:

- нет `auto_submit` и флага «нажать за пользователя»;
- нет инструмента `crm.save`, `crm.send`, `crm.delete`, `crm.message`;
- нет отправки сообщений клиенту и нет интеграции с мессенджерами;
- максимальное действие — `fill`, `click("+")` и открытие окна задачи;
- после заполнения человек проверяет карточку и сам нажимает «Сохранить» или
  «Создать задачу».

Ошибки не скрываются: каждое поле получает `ok/error`, инструмент возвращает
`ok=False`, если хотя бы одно поле не заполнилось, а `meta.saved` всегда
`False`.

## 5. Инструменты `crm.*`

| Инструмент | Риск | Capability | Аргументы | Поведение |
|---|---|---|---|---|
| `crm.read` | R1 | `crm.read` | `order_url` (необязательно) | текст карточки, `trust="untrusted:crm"`, санитайзер |
| `crm.fill` | R2 | `crm.write` | `comment` ≤ 5000, `checklist` (только known labels) | заполнить, вернуть «filled, not saved» |
| `crm.act` | R2 | `crm.write` | `rows` 1..20: `name`, `price`, `warranty` | добавить строки акта, без сохранения |
| `crm.task` | R2 | `crm.write` | `comment` 1..500, `when_text` ≤ 100 | заполнить окно, не создавать |

`crm.read`:

- без аргументов читает открытую вкладку; `order_url` — необязательный guard:
  если фактический URL не содержит подстроку, результат `ok=False`;
- текст проходит `sanitize_text`, подозрительные фразы попадают в
  `meta.suspicious`, но не меняют решение политики;
- поля карточки тоже очищаются; `url` не логируется.

`crm.fill`, `crm.act`, `crm.task`:

- `R2` означает обязательное подтверждение в `ToolExecutor`; в тестах это
  проверяется без `approved`;
- значения не попадают в preview и в метаданные: dry-run показывает только
  количество символов и имена полей/строк;
- `dry_run` не создаёт клиент и не трогает страницу;
- все четыре инструмента собираются
  [`build_crm_tools()`](../src/kivi/modules/work_crm/tools.py) и делят один
  ленивый `CrmSession`; `client_factory` подставляет fake-клиент в тестах.

`compose_draft(facts)` — детерминированный мост к `drafts.py`: вызывает
`build_comment`, `build_checklist`, `build_act_rows`, `build_task` и
`price_check`, возвращает `CrmDraft` с готовыми `fill_args()`, `act_args()`,
`task_args()`. Никаких страниц и сети.

Инструменты **ещё не зарегистрированы** в общем registry/CLI: это отдельный
шаг интеграции. Пример прямого вызова через executor:

```python
from kivi.modules.work_crm.tools import build_crm_tools

tools = build_crm_tools()                  # браузер ещё не запущен
for tool in tools:
    registry.register(tool)
# executor.run("crm.read", {}, grant=grant)
# executor.run("crm.fill", {...}, grant=grant, approved=True)
```

## 6. Политика и безопасность

- **Заполнение разрешено, сохранение — нет.** R2 + approval покрывают
  изменение полей; финальное действие остаётся за человеком.
- **Никаких сообщений клиенту.** Нет `send`, нет мессенджеров, нет телефонии.
- **Никаких секретов.** Пароли не читаются и не хранятся; URL и токены не
  пишутся в лог. Ошибка соединения намеренно не содержит `cdp_url`.
- **Никакого произвольного JS.** Только `inner_text`, `fill`, клики по
  безопасному тексту и чтение `input_value`.
- **Никаких селекторов от LLM.** Набор меток закрыт, CSS-классы берутся из
  конфига, инструменты не принимают `selector`.
- **Один браузер, одна вкладка.** `connect_over_cdp` к существующему Chrome;
  новые страницы и профили не создаются. `close()` не закрывает браузер.
- **Аудит.** Каждый вызов идёт через `ToolExecutor` и пишет решение политики
  и результат; `trust="untrusted:crm"` не даёт тексту страницы управлять
  агентом.

## 7. Ограничения

1. **Angular/PrimeNG дрейфует.** Placeholder, порядок полей, классы строки
   акта и границы диалога могут измениться после обновления CRM. Симптом —
   `ok=False` с ошибкой «поле не найдено» или «полей гарантии: 0». Лечение —
   обновить `AltCrmConfig.selectors`; код не меняется.
2. **Нет реальной CRM в CI.** Все 63 теста используют fake-страницу или
   fake-клиент. Они
   проверяют логику, политику и отказ от опасных кликов, но не реальную
   вёрстку. Перед использованием проверьте `crm.read` и один `crm.fill` на
   тестовом заказе.
3. **Нет пути через расширение.** Старый `crm_ext.py`/`extension/content.js`
   не портированы. Адаптер требует CDP и отдельный профиль с открытым
   debugging-портом; это осознанный компромисс ради отсутствия расширения и
   фонового моста.
4. **Выбор вкладки.** Берётся последняя вкладка, чей URL содержит подстроку.
   Держите открытой одну карточку заказа; при нескольких подходящих вкладках
   результат может относиться не к той.
5. **Проверка значения.** После `fill` сравнивается `input_value()`. Если
   Angular переформатирует значение (пробелы, маска), адаптер честно вернёт
   ошибку, хотя визуально поле заполнено.
6. **Срок задачи.** Поддерживаются явные даты и короткие относительные
   фразы; быстрые кнопки `+15 мин`/`+24 часа` не нажимаются. Непонятный срок
   остаётся на ручную правку.
7. **Цена и гарантия.** Нулевая цена — сигнал «введите вручную»; адаптер не
   придумывает сумму. `price_check` из `drafts.py` предупреждает о
   расхождении, но не блокирует заполнение.
8. **Один поток.** Синхронный Playwright требует одного потока; инструменты
   вызываются последовательно через executor. Параллельные вызовы одного
   клиента не поддерживаются.
