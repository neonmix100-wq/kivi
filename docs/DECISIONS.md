## 2. Что означает A4 на практике

«Полная автономия» не может означать «модель сама решает, можно ли удалить Windows».
Модель можно обмануть через prompt injection, и тогда ограничения, написанные в промпте, не спасут.
Поэтому принимаем **A4-Bounded**:

> Внутри разрешённых областей Kivi действует без подтверждений и может строить длинные цепочки действий.
> За пределами — **жёсткий отказ**, а не «спросить разрешение».
> Несколько действий запрещены всегда, даже при A4.

### 2.1. Что разрешено без подтверждений

- чтение/запись/поиск в разрешённых папках;
- запуск разрешённых программ и команд;
- браузер, почта, Telegram в рамках выданных прав;
- код в песочнице;
- генерация медиа;
- работа с CRM в разрешённых операциях.

### 2.2. Жёсткие запреты (hard stops)

- `C:\Windows`, `C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData\Microsoft`;
- загрузчик, EFI, разделы дисков, `diskpart`, `format`, `bcdedit`;
- системный реестр (HKLM), драйверы, службы, политики безопасности;
- удаление/отключение антивируса, бэкапов, аудита;
- чтение и отправка секретов: пароли, токены, ключи SSH/GPG, хранилища браузера;
- изменение `safety`-ядра, журнала аудита и списка запретов агентом;
- деньги сверх установленного лимита, необратимые внешние действия без политики.

Для этих действий существует только **ручной break-glass режим**: пользователь сам запускает операцию через отдельный интерфейс с Windows Hello/паролем. Агент не может инициировать его самостоятельно.

### 2.3. Список запретных мест

- Хранится отдельно от конфигурации агента, подписан, доступен только на чтение ядру.
- Редактируется пользователем через UI с подтверждением личности.
- Изменения применяются после перезапуска и пишутся в аудит.
- Агент не может добавить себя в исключения или отключить проверку.
- Проверка путей: канонизация, запрет `..`, симлинков, junction, hardlink, UNC, 8.3-имён и alternate data streams.

### 2.4. Почему не «просто запустить всё от администратора»

Права администратора Windows — это членство в группе Administrators и повышение через UAC.
Процесс «от администратора» может:

- менять `C:\Windows`, `Program Files`, реестр HKLM;
- устанавливать драйверы и службы;
- менять политики безопасности;
- читать файлы других пользователей;
- отключать защиту.

Если Kivi работает всё время с такими правами, любая ошибка модели, баг или внедрённая инструкция может повредить систему.
**Рекомендация:** ядро и аватар — с обычными правами; для редких admin-задач — отдельный `elevated broker`:

- запускается по требованию, с UAC;
- умеет только узкий список операций;
- каждая операция подтверждается и логируется;
- не даёт «произвольный PowerShell от администратора».

Это не мешает «практически полному доступу»: файлы пользователя, программы, браузер, буфер, окна, микрофон, камера — доступны без admin.
Admin нужен для установки драйверов, служб, системных настроек и некоторых установщиков.

### 2.5. Защита от prompt injection

Принята многослойная схема (детали — `docs/SECURITY.md`):

- текст не является полномочием; права выдаёт только пользователь или политика;
- недоверенный контент (web, файлы, письма, OCR, код, tool output) помечается и очищается;
- карантинный читатель без инструментов превращает контент в факты с цитатами;
- модель предлагает действие, Policy Engine проверяет и выполняет;
- высокорисковые действия — подтверждение с точным действием и источником;
- egress-контроль не даёт уйти секретам и Protected Zones;
- память имеет provenance; внешние факты не становятся доверенными автоматически;
- 100+ тестов injection, canary-утечки, path traversal, memory poisoning.

## 3. Облако: только бесплатные лимиты

### 3.1. Как это будет работать

```
задача → Cloud Broker
           ├─ локальная модель справляется → локально
           ├─ есть бесплатный лимит и провайдер разрешён → вызов
           ├─ лимит исчерпан / 429 / ошибка → checkpoint
           │     → handoff pack
           │     → Cloud Scout: найти нового бесплатного провайдера
           │         ├─ нашёл → карточка провайдера → подтверждение → продолжить
           │         └─ не нашёл → локальная модель продолжает с того же места
           └─ провайдер не разрешён → только локально
```

**Handoff pack** содержит:

- цель и критерии успеха;
- план и выполненные шаги;
- артефакты и ссылки;
- краткую сводку диалога;
- ограничения и запреты;
- следующий ожидаемый шаг.

Он сохраняется в SQLite и передаётся локальной модели. Задача не «теряется» при исчерпании лимита.

**Cloud Scout** — отдельный шаг после исчерпания лимита:

1. Ищет бесплатные провайдеры под тип задачи (LLM, картинки, видео, embeddings).
2. Проверяет: бесплатный лимит, условия, лицензию, watermark, ограничения, политику данных.
3. Готовит карточку провайдера: что умеет, сколько бесплатно, что требуется, риски.
4. Пользователь подтверждает и добавляет ключ; Kivi не создаёт аккаунты и не обходит CAPTCHA.
5. Если провайдер найден и разрешён — задача продолжается в облаке.
6. Если нет — локальная модель продолжает с handoff pack.

Cloud Scout не является «самостоятельным агентом с правами»: он только исследует и предлагает.
Решение о подключении нового провайдера принимает пользователь.

### 3.2. Что реально бесплатно

Бесплатные тарифы меняются, требуют аккаунтов, телефона и часто **используют данные для обучения**.
Типичные варианты:

- LLM: OpenRouter free-модели, Google AI Studio, Groq, Mistral, Cloudflare Workers AI, Hugging Face credits;
- картинки: Pollinations, Stable Horde, Hugging Face Spaces, free credits у сервисов;
- видео: чаще одноразовые credits, watermark, ограничение длины; официальные API обычно платные.

Kivi может **искать и предлагать** бесплатные инструменты, но:

- не создаёт аккаунты автоматически;
- не обходит CAPTCHA и лимиты;
- не нарушает ToS;
- добавляет провайдера только после подтверждения пользователя и получения ключа.

### 3.3. Приоритет

1. Локальная модель, если качество достаточное.
2. Бесплатный облачный провайдер, если локально не хватает мощности/качества.
3. Локальный fallback с handoff pack.
4. Честный отчёт: «бесплатный лимит исчерпан, вот что сделано, вот что дальше».

## 4. Персона Kivi

- Имя: **Kivi**.
- Голос: женский, русский.
- Стиль: спокойный, живой, без канцелярита.
- По умолчанию — краткий ответ (1–3 предложения) и предложение: «Рассказать подробнее?»
- Если вопрос технический/кодовый или пользователь просит — подробно.
- Не переспрашивать без необходимости; уточнять только при реальной неоднозначности.
- Анимация речи обязательна; 3D-аватар — цель, 2D-заглушка — на старте.
- Аватар: 18 лет, 156 см, бирюзовые волосы и глаза, реалистичный аниме, без аксессуаров;
  всегда на рабочем столе, отдельное окно, второй монитор, скрытие по запросу.
- Голос: женский, мягкий, спокойный; сэмплы в `assets/voice-samples/`.
- Подробности: `docs/PERSONA.md`.

## 6. Апгрейд железа

Планируется через 1–2 месяца:

- GPU: пользователь указал **MSI RTX 3070** и «12 ГБ VRAM»;
- SSD: внутренний **M.2 NVMe 1 ТБ**.

### 6.1. Важное уточнение по RTX 3070

**RTX 3070 — это 8 ГБ VRAM, а не 12 ГБ.** У неё 8 ГБ GDDR6 и 256-битная шина.
12 ГБ у RTX 3060 (12 ГБ), RTX 4070 (12 ГБ), RTX 5070 (12 ГБ); 16 ГБ — у RTX 4060 Ti 16 ГБ
и RTX 4070 Ti Super.

Если купить RTX 3070, Kivi будет работать, но:

- 8B Q4 + ASR + браузер + аватар — тесно;
- 14B — только частичный offload, медленно;
- SDXL и видео — по очереди, не одновременно с LLM;
- запас на будущее почти нулевой.

Варианты (проверить актуальные цены и наличие):

| Вариант | VRAM | Плюсы | Минусы |
|---|---|---|---|
| RTX 3060 12GB | 12 | дешёвый вход в 12 ГБ | медленнее 3070, старый чип |
| RTX 4070 12GB | 12 | быстрый, эффективный | цена выше |
| RTX 4060 Ti 16GB | 16 | 16 ГБ для LLM/SDXL | 128-битная шина, слабее в играх |
| RTX 5070 12GB | 12 | новый чип, GDDR7 | цена/наличие, новый БП |
| RTX 4070 Ti Super 16GB | 16 | быстрый + 16 ГБ | дорого |
| Б/у RTX 3090 24GB | 24 | максимум VRAM за деньги | нагрев, БП, риск б/у |

**Рекомендация:** если бюджет позволяет — **RTX 4060 Ti 16GB** или **RTX 4070 12GB**.
Если нужен минимальный бюджет — **RTX 3060 12GB**. RTX 3070 8GB брать только если она
сильно дешевле и вы готовы к ограничениям 8 ГБ.

### 6.2. SSD

- Внутренний M.2 NVMe 1 ТБ — правильный выбор.
- Проверить: свободный слот M.2, PCIe-поколение, длину, ключ (M/B), охлаждение.
- Модели и кэш держать на новом диске; OS — на C:.
- 1 ТБ хватит на LLM + SDXL + видео + бэкапы, но не на «зоопарк» всех моделей.

### 6.3. Блок питания

- RTX 3070/4070 — ориентир 650 Вт качественного БП.
- RTX 4060 Ti 16GB — 550–600 Вт.
- RTX 3090 — 750–850 Вт, хорошее охлаждение корпуса.
- Проверить разъёмы питания и возраст БП.

### 6.4. Что это меняет для Kivi

- 12 ГБ — комфортнее 8B + ASR, иногда 14B с offload;
- 16 ГБ — SDXL + LLM по очереди без постоянной выгрузки, 14B реалистичнее;
- 24 ГБ — можно думать о 32B Q4 и видео, но это уже другой бюджет;
- аватар и браузер всё равно требуют резерва;
- видео 1080p локально — не гарантировано даже на 16 ГБ.

До апгрейда бюджеты считаем по 8 ГБ; после — пересматриваем `models.yaml`.

## 7. ОС и псевдо-ОС

- Сейчас — **Windows 11** как хост: CRM, Office, игры, драйверы.
- Linux-инструменты — через **WSL2**.
- **Kivi Shell — полноэкранная замена Explorer**, а не просто лаунчер.
  Требование: сохранить все функции Explorer, чтобы ПК оставался полностью рабочим.
- Explorer не удаляем: он остаётся аварийной оболочкой.
- Внедрение стадиями:
  1. полноэкранное приложение (Explorer работает);
  2. beta-замена оболочки с аварийным возвратом;
  3. оболочка по умолчанию после 7-дневного soak-теста.
- Аварийный возврат: `Ctrl+Alt+Shift+E` + автоматический fallback при падении.
- Для замены shell нужен admin — через elevated broker, с точкой восстановления.
- Ядро пишем с абстракцией платформы, чтобы позже можно было вынести на Linux.
- Полноценная Linux-ОС или dual-boot — отдельное решение позже; сначала измерим, что именно тормозит.

Детали, матрица паритета и риски: `docs/SHELL.md`.

## 8. Модуль работы

`D:\ai-agent` — не форкаем целиком, а **разбираем на headless-домен + UI**:

- `work_crm/domain`: факты, черновики, коуч, история, парсинг звонков;
- `work_crm/adapters`: AltCRM (расширение браузера, Playwright);
- `work_crm/tools`: чтение заказа, заполнение карточки, акт, задача, прослушивание звонков;
- `work_crm/ui`: панель в Kivi;
- старый `ai-agent` работает как есть, пока новый модуль не достигнет паритета.

Модуль подключается через версионированный Plugin API (`docs/MODULES.md`), чтобы его можно было обновлять и откатывать.

Автоматизация заказов — в первую очередь:

1. заполнение карточки заказа;
2. комментарий менеджера;
3. чек-лист менеджера;
4. статус заказа;
5. акт работ;
6. постановка новой задачи.

Всё, кроме прямого общения с клиентом. В будущем — попробовать и общение, но только
с отдельной политикой, проверкой и правом человека отменить.

Режим:

- сначала — «Kivi готовит, человек подтверждает»;
- затем A4 для рутины (чтение, факты, черновики, заполнение разрешённых полей);
- сохранение/отправка/удаление/оплата/скидки — по отдельной политике;
- цель — убрать рутину, а не отдать деньги и юридические решения без контроля.

Поля и действия, которые Kivi может менять автоматически, задаются в манифесте модуля
и в политике `work_crm`, а не в промпте.

## 9. Следствия для архитектуры

Добавляются подсистемы:

1. **Cloud Broker** — бесплатные провайдеры, квоты, handoff.
2. **Protected Zones** — жёсткие запреты, подписанный список.
3. **Elevated Broker** — admin-операции.
4. **Avatar/Presence** — TTS, липсинк, состояния, 3D-модель.
5. **Plugin API** — модули, включая work_crm.
6. **Kivi Shell** — псевдо-ОС.
7. **Platform Abstraction** — Windows сейчас, Linux позже.

## 11. Оставшиеся вопросы

1. **Голос:** какой сэмпл нравится — Piper `irina`, Windows SAPI `Irina`, Edge `Svetlana`
   или Silero `baya`/`kseniya`/`xenia`?
2. **Одежда:** какой из 5 вариантов (`docs/PERSONA.md`) выбрать? Или комбинация?
3. **Shell:** режим внедрения A → B → C — ок? Где аватар (справа/слева/центр)?
   Панель задач снизу или своя? Нужны ли сторонние контекстные меню (7-Zip/Git)?
4. **GPU:** подтвердить выбор с учётом того, что RTX 3070 — 8 ГБ.
   Готовы ли рассматривать 4060 Ti 16GB / 4070 12GB / 3060 12GB?
5. **Почта:** какой провайдер (Gmail/Outlook/Яндекс/корпоративный)? IMAP/SMTP или OAuth?
   Отправлять автономно или только черновики?
6. **Облако:** какие бесплатные сервисы завести первыми? Kivi может подготовить список
   и карточки, но аккаунты создаёт пользователь.
7. **CRM:** подтвердить домен AltCRM, доступные поля и селекторы; нужны ли реальные
   тестовые заказы для отладки.
