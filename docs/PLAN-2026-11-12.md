## 2. Что изменилось относительно прошлого плана

| Было (план) | Стало (факт) | Следствие |
|---|---|---|
| RTX 3060 Ti 8 ГБ | **RTX 4060 Ti 16 ГБ** | +8 ГБ VRAM; 8B Q4, 14B Q4, SDXL и Whisper стали реалистичны |
| 1,8 ГБ свободной VRAM | ~14,5 ГБ | больше не нужно закрывать браузер ради 4B |
| 8B Q4 упиралась в 8 ГБ | 8B Q4 — 9,7 ГБ | 8B Q4 — основной чат |
| SDXL «потом» | SDXL ~6,8 ГБ | M7 можно делать локально уже сейчас |
| 14B «с offload» | 14B Q4 @8192 — **14,3 ГБ, 14,6 tok/s** | качественный чат, но без ASR/аватара |
| D: 126 ГБ | D: 100,5 ГБ | 14B + SDXL + whisper + VL + Qwen3-TTS помещаются, датасеты — нет |

Главное: **16 ГБ снимают VRAM-ограничение, но не ограничение по CPU (4 ядра)
и не проблему нехватки ассетов** (VRM, wake ONNX, реальный AltCRM).

## 3. Новый baseline (12.11.2026)

| Модель | Контекст | Загрузка | Tokens/s | Peak VRAM |
|---|---:|---:|---:|---:|
| `qwen3.5:4b` | 8192 | 5.35 с | 54.3 | 7 787 МБ |
| `Qwen3-8B Q4_K_M` | 8192 | 5.72 с | 38.2 | 9 731 МБ |
| `qwen2.5-coder:7b` | 16384 | 4.72 с | 43.4 | 9 043 МБ |
| `Qwen3-14B Q4_K_M` | 8192 | 15.61 с | 14.6 | 14 295 МБ |
| `Qwen2.5-Coder-14B Q4_K_M` | 16384 | 8.34 с | 21.4 | 15 326 МБ |

Выводы:

- **8B Q4 — основной чат** (быстрее 14B и оставляет VRAM под ASR/аватар);
- 14B Q4 — качественный режим, но 14,3 ГБ и 14,6 tok/s;
- **7B coder @16k — быстрый Coder**; Coder-14B — качественный, 15,3 ГБ;
- 4B @8k занимает 7,8 ГБ — для router лучше 4096, чтобы не тратить VRAM;
- первый холодный запуск может быть в 5–10 раз дольше; в метриках отделять
  cold load от warm.

помещаются, 8B Q4 + SDXL (~16,5 ГБ) — нет.

## 5. Приоритеты

### P0 — уже сделано (12.11.2026)

### P1 — 14B и модели (частично сделано 12.11.2026)

Установлено:

| Модель | Размер | Замер |
|---|---:|---|
| `Qwen3-14B Q4_K_M` | 9,0 ГБ | 8192: 14,6 tok/s, 14 295 МБ |
| `Qwen2.5-Coder-14B Q4_K_M` | 9,0 ГБ | 8192: 21,6 tok/s, 13 919 МБ; 16k: 21,4 tok/s, 15 326 МБ |
| `Qwen3-VL-8B Q4_K_M` | 5,8 ГБ | vision, projector clip, 5 575 МБ |
| `Qwen3-TTS 1.7B VoiceDesign/Base` | 8,4 ГБ | голос Kivi, 3 reference-сэмпла |
| `faster-whisper-large-v3-turbo` | 1,54 ГБ | CPU int8: 11,7 с речи распознано |
| SDXL base 1.0 | 6,46 ГБ | чекпойнт установлен |

Осталось:

1. Проверить 8B Q4 + Whisper + 3D-аватар одновременно.
2. Запустить SDXL через ComfyUI/SD WebUI и замерить 1024×1024, 20 steps.
3. Проверить Qwen3-VL на реальных скриншотах/PDF-страницах.
4. Сравнить 14B и 8B Q4 на русском/коде и выбрать дефолт по задаче.

**Приёмка:** 14B работает ≥ 14 tok/s при 8192 без OOM; Coder-14B — ≥ 20 tok/s;
8B + ASR + аватар помещаются; SDXL генерирует 1024×1024 без shared memory.

### P2 — M7 Cloud Media (3–5 дней)

Теперь это самый разблокированный крупный этап.

1. Локальный SDXL через ComfyUI/SD WebUI: `image.generate`, 1024×1024, 20 steps.
2. Бесплатные облачные image/video-провайдеры через Cloud Broker с квотами.
3. 10 сценариев: аватар, иллюстрация, обложка, фото-ретушь, видео-клип.
4. Метрики: время, VRAM, стоимость (0), доля успешных.

**Приёмка:** 10 сценариев, ни одного платного вызова без разрешения,
SDXL не запускается одновременно с 8B.

## 7. Метрики и приёмка

- 14B: warm load < 8 с, ≥ 20 tok/s, без OOM.
- 8B Q4 + Whisper + 3D-аватар: ≤ 13,5 ГБ peak, без shared memory.
- SDXL 1024×1024: ≤ 60 с на 20 steps, ≤ 7,5 ГБ.
- 10 image/video-сценариев M7.
- 10 реальных заказов M6 — только при доступе к AltCRM.
- false wake < 1/час, WER, voice command < 3 с — после микрофона/моделей.
- `pytest -q` и `ruff check src tests` — зелёные на каждом шаге.
