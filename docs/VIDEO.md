# Видео (M7): ЛОКАЛЬНЫЙ FALLBACK — короткий MP4 из одной картинки

> **LOCAL FALLBACK, а не text-to-video.** Инструмент `media.video` не умеет
> генерировать движение по тексту. Он просит у того же бесплатного
> Pollinations **одну** картинку (как `media.image`), а затем **локально**
> анимирует этот единственный кадр медленным zoom'ом через ffmpeg из
> `imageio-ffmpeg`. Настоящего видео-провайдера, внешнего video API, ключа,
> аккаунта и загрузки файлов здесь нет.

Этот срез закрывает M7 «видео» настолько, насколько это возможно без внешних
видео-сервисов: пользователь получает валидный H.264 MP4, который можно
отправить в мессенджер или открыть в плеере, но это **не** генерация сцены по
описанию. Ограничения честно перечислены в разделе 8.

Модули:

- `src/kivi/tools/video.py` — `VideoGenerateArgs`, `MediaVideoTool`, сборка
  URL кадра, политика промптов, фиксированный argv ffmpeg, проверка MP4;
- `tests/unit/test_video.py` — тесты без сети и без запуска ffmpeg;
- этот документ.

## 1. Что это даёт и чего не даёт

| Вопрос | Ответ |
|---|---|
| Нужен внешний video API? | **Нет.** Только публичный image GET Pollinations. |
| Нужен API-ключ, аккаунт, биллинг? | **Нет.** |
| Это генерация видео по тексту? | **Нет.** Это motion-fallback из одного кадра. |
| Есть движение? | Да, медленный zoom (zoompan), кадр «дышит». |
| Можно управлять движением/сценой? | Нет. Ни камеры, ни смены плана, ни morphing. |
| Watermark? | Kivi свой watermark не добавляет; `nologo=true` просит провайдера не добавлять его логотип, но провайдер может менять поведение. |
| Аудио? | Нет. Дорожка отключена (`-an`). |
| Длительность | Целое число секунд 2..8 (по умолчанию 4). |
| Разрешение | 512×512 или 768×768 (по умолчанию 512×512), квадрат. |
| Контейнер/кодек | MP4 (`ftyp`), H.264 High, `yuv420p`, `+faststart`. |
| FPS | 24. |

## 3. Архитектура

```text
пользователь / planner (trusted:user)
        │  media.video(prompt, width, height, duration, model, seed)
        ▼
ToolExecutor  (capability media.generate, риск R1, аудит каждого вызова)
        ▼
MediaVideoTool
  ├─ политика промпта (control chars, denylist как у media.image)
  ├─ build_source_url  ── фиксированный хост image.pollinations.ai
  ├─ httpx.Client(timeout=120, follow_redirects=False) ── один GET картинки
  ├─ проверка 200 / image/* / magic bytes / <= 10 МБ
  ├─ `imageio_ffmpeg.get_ffmpeg_exe()`  ── локальный бинарник, без сети
  ├─ save data/media/video-src-<uuid>.jpg
  ├─ ffmpeg: -loop 1 -i image -t N -vf zoompan=... (фиксированный argv)
  ├─ проверка MP4 (ftyp), размера (<= 40 МБ); удаление промежуточного кадра
  └─ data/media/kivi-<uuid>.mp4
        ▼
ToolResult(ok, artifacts=[mp4], trust="untrusted:web")
```

- Инструмент не вызывает другие инструменты и не видит БД: путь один — через
  `ToolExecutor`, поэтому permission-проверка и аудит обязательны.
- Никаких ключей: запрос к Pollinations — обычный публичный GET, а кодирование
  целиком локальное.
- Локальные файлы не загружаются: у аргументов нет пути, URL или файла,
  `extra="forbid"` отвергает любые лишние поля. Пути к кадру и MP4 генерирует
  сам инструмент (UUID), а не модель или пользователь.

## 4. Аргументы

`VideoGenerateArgs` — Pydantic-модель с `extra="forbid"`.

| Поле | Тип | По умолчанию | Ограничения |
|---|---|---|---|
| `prompt` | `str` | — | 1..500 символов, обрезается по краям |
| `width` | `Literal[512, 768]` | `512` | только 512 или 768 |
| `height` | `Literal[512, 768]` | `512` | только 512 или 768 |
| `duration` | `int` | `4` | 2..8 секунд |
| `model` | `Literal["flux", "turbo"]` | `"flux"` | только два значения |
| `seed` | `int \| None` | `None` | 0..2 147 483 647; без `seed` — случайный кадр |

Пример:

```json
{
  "prompt": "a red fox in snow, soft morning light",
  "width": 768,
  "height": 768,
  "duration": 6,
  "model": "flux",
  "seed": 42
}
```

Лишние поля (`path`, `url`, `image`, `ffmpeg_args`, …) падают с
`ValidationError`: подсунуть локальный файл или флаг ffmpeg нельзя.

Риск — **R1**: инструмент создаёт новый файл внутри workspace. Capability —
`media.generate`, как у `media.image` и `media.sdxl`.

## 5. Кадр-источник

Хост зашит в код и совпадает с `media.image`:

```text
https://image.pollinations.ai/prompt/<percent-encoded prompt>?width=...&height=...&model=...&nologo=true[&seed=...]
```

- `prompt` кодируется через `urllib.parse.quote(..., safe="")`, поэтому `/`,
  `?`, `#`, `%`, пробелы и не-ASCII не могут изменить путь или хост.
- `width`, `height`, `model`, `nologo=true` передаются всегда; `seed` —
  только если задан.
- Хелперы `build_image_url()` и `detect_image_type()` импортируются из
  `kivi.tools.media`, denylist — `DEFAULT_PROMPT_DENYLIST` оттуда же. Проверки
  control-символов и нормализация слов продублированы минимально (они приватные
  в `media.py`, как и в `sdxl.py`).
- Ответ валидируется до записи: статус ровно 200 (3xx — ошибка, редиректы не
  выполняются), `content-type` из `image/png`, `image/jpeg`, `image/webp`
  (алиасы `image/jpg`, `image/pjpeg`), настоящие magic bytes, тело непустое,
  размер ≤ **10 МБ**.
- Кадр сохраняется как `data/media/video-src-<uuid>.jpg` и удаляется после
  кодирования (и при ошибке тоже): это промежуточный файл, а не артефакт.
  ffmpeg определяет реальный формат по содержимому, поэтому PNG/WebP-ответ
  тоже обрабатывается, хотя имя остаётся `.jpg` из соображений
  предсказуемости.

## 6. Локальная сборка MP4

Используется ровно одна команда, собранная в `build_ffmpeg_argv()`:

```text
<ffmpeg> -hide_banner -nostdin -loglevel error -y
         -loop 1 -i <video-src-uuid>.jpg
         -t <duration>
         -vf zoompan=z='min(zoom+0.0008,1.08)':d=1:s=<W>x<H>:fps=24
         -c:v libx264 -pix_fmt yuv420p -movflags +faststart
         -an
         <kivi-uuid>.mp4
```

- `-loop 1` — бесконечный вход из одного кадра, `-t` обрезает выход до нужной
  длительности; `zoompan` медленно увеличивает масштаб (0.0008 за кадр, максимум
  1.08), `d=1` — один выходной кадр на входной, `s=WxH` — размер, `fps=24`.
- Одинарные кавычки вокруг выражения `zoompan` — часть аргумента, а не shell:
  они защищают запятую внутри `min(...)` от парсера фильтров ffmpeg.
  `shell=False`, argv передаётся списком, `stdin` закрыт (`-nostdin`).
- `libx264` + `yuv420p` + `+faststart` — совместимый H.264 MP4, готовый к
  прогрессивной загрузке. `-an` — без аудиодорожки.
- Вызывающий не может добавить ни один флаг: в модели аргументов нет ни argv,
  ни filter, ни codec, ни пути. Всё, что попадает в команду, — это
  UUID-имена файлов, размер 512/768, длительность 2..8 и путь к бинарнику.
- `ffmpeg_runner=` — точка инъекции для тестов: callable
  `(argv, out_path) -> None`. По умолчанию используется `run_ffmpeg()`
  (`subprocess.run` с `shell=False`, `capture_output=True`, таймаут 120 с).
- Проверено вживую на `ffmpeg-win-x86_64-v9.0.2.exe` из `imageio-ffmpeg 0.8.1`:
  512×512 / 4 с и 768×768 / 8 с дают ровно `Duration: 00:00:04.00` и
  `00:00:08.00`, `h264`, 24 fps. На full-range JPEG ffmpeg может пометить поток
  как `yuvj420p` (то же 8-битное 4:2:0, полный диапазон) — это нормально для
  такого входа и воспроизводится стандартными плеерами.

## 7. Проверка результата

После кодирования инструмент проверяет:

1. **Файл существует и не пуст.** Иначе — `ToolError`.
2. **Размер ≤ 40 МБ** (`MAX_VIDEO_BYTES`). Иначе файл удаляется, вызов
   возвращает `ok=False`.
3. **MP4 magic.** В первых 12 байтах должен быть box `ftyp`
   (`data[4:8] == b"ftyp"`). Иначе — `ToolError`, файл удаляется.
4. **Атомарность.** Временных «полу-MP4» не остаётся: при ошибке файл
   удаляется, при отмене — тоже. Промежуточный кадр удаляется всегда.

`ToolResult.meta`:

| Ключ | Значение |
|---|---|
| `path` | абсолютный путь к MP4 |
| `bytes` | размер MP4 |
| `duration` | запрошенная длительность, секунды |
| `width`, `height` | 512 или 768 |
| `fps` | 24 |
| `model`, `seed` | параметры кадра |
| `source_url` | URL, с которого получен кадр |
| `source_type` | `image/jpeg`, `image/png` или `image/webp` |
| `source_bytes` | размер исходного кадра |
| `encoder` | `ffmpeg` |
| `external_video_api` | `false` |
| `max_bytes` | 40 МБ |

`trust="untrusted:web"`: клип — это данные из интернета, а не команда. Даже если
в кадре «нарисован текст», он не имеет права инструктировать планировщик.

## 8. Ограничения

- **Это не text-to-video.** Один кадр + zoom. Нет движения объектов, смены
  планов, физики, морфинга и согласованности между кадрами.
- Только **квадрат** 512×512 или 768×768. Другие размеры и пропорции
  отвергаются валидацией.
- Только **2..8 секунд** целым числом. Более длинный клип — это больше кадров
  при том же одном изображении, без нового содержания.
- **24 fps**, **без звука**, без субтитров и без наложения текста.
- **Один запрос** к Pollinations на вызов, без ретраев. Лимиты бесплатного
  сервиса общие для `media.image`/`media.video`.
- Кадр ограничен **10 МБ**, MP4 — **40 МБ**; при превышении вызов падает, а не
  обрезает файл.
- Качество и содержание кадра определяет провайдер. Denylist — грубая
  эвристика, а не классификатор; ответственность за промпт остаётся на
  пользователе.
- Провайдер может менять поведение `nologo`, модели и доступность без
  предупреждения. Гарантий SLA нет.

## 9. ffmpeg через imageio-ffmpeg

- Зависимость — пакет **`imageio-ffmpeg`** (в проекте стоят `imageio 2.38.1` и
  `imageio-ffmpeg 0.8.1`); отдельный системный ffmpeg не нужен.
- Путь к бинарнику берётся только через `imageio_ffmpeg.get_ffmpeg_exe()`
  (`resolve_ffmpeg()`), импорт ленивый: модуль импортируется и без пакета.
- В текущем окружении это
  `.venv\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v9.0.2.exe`.
- Установка, если пакета нет:

  ```powershell
  .venv\Scripts\python.exe -m pip install imageio-ffmpeg
  ```

- Если бинарник отсутствует или пакет сломан, инструмент возвращает понятный
  `ToolError`: «ffmpeg binary not found: install the imageio-ffmpeg package
  (pip install imageio-ffmpeg) and retry…». Проверка выполняется **до**
  скачивания кадра, поэтому сеть не тратится зря.
- Таймаут кодирования — 120 секунд. Для 2..8 секунд 512/768 этого достаточно с
  большим запасом (вживую — доли секунды).
- Кодирование полностью локальное: ни кадр, ни MP4 никуда не отправляются.

## 10. Приватность, лицензии и ToS

- Промпт уходит на сторонний сервис по HTTPS (Pollinations). Не вставляйте в
  промпт секреты, токены, пароли, персональные данные и содержимое приватных
  файлов.
- Kivi не передаёт API-ключ (его нет), не загружает локальные файлы и не
  отправляет видео: наружу уходит только текст промпта и параметры кадра.
- Провайдер может логировать запросы и хранить/публиковать изображения по своим
  правилам. Политика Pollinations и лицензии моделей (`flux`, `turbo`)
  применяются напрямую; перед коммерческим использованием результата проверьте
  их.
- Watermark: Kivi ничего не накладывает. `nologo=true` — просьба к провайдеру
  не добавлять свой логотип, но это не гарантия: бесплатный сервис может
  изменить поведение параметров.
- ffmpeg-бинарник из `imageio-ffmpeg` распространяется под своей лицензией
  (сборка FFmpeg; см. лицензию пакета). При распространении клипов учитывайте
  лицензии кодека/сборки и правила площадки.
- Запрещены NSFW/sexual-контент с участием несовершеннолетних, обход фильтров,
  авто-регистрация, обход CAPTCHA, мультиаккаунтинг и любые действия против ToS
  провайдера. Denylist и проверки — лишь первый барьер.
- Сгенерированный клип может быть неточным, оскорбительным или нарушающим
  чужие права. Это `untrusted:web`-данные, а не факт.

## 11. Тесты

```powershell
.venv\Scripts\python.exe -m pytest -q tests\unit\test_video.py
```

Тесты не ходят в сеть и не запускают настоящий ffmpeg:

Покрыто: метаданные инструмента и схема аргументов, дефолты, невалидные

MP4 и удаление промежуточного кадра, уникальные имена выходов, `dry_run` без
сети/файлов и с политикой промптов, заблокированный промпт до запроса,
control-символы, HTTP-ошибка, редирект, не-image, неподдерживаемый image-тип,

отсутствие `ftyp`, превышение 40 МБ, `resolve_ffmpeg`, `is_mp4_header`,
R1-аудит и отказ без capability `media.generate`.

## 12. Интеграция

Сам срез добавляет только `video.py`, тесты и этот документ: `registry.py` и
CLI не редактировались. Регистрация сделана отдельным интеграционным шагом —
в текущем рабочем дереве `MediaVideoTool()` уже включён в `build_registry()`,
а CLI получил команду `kivi media video`. Подключение выглядит так:

```python
# src/kivi/tools/registry.py, внутри build_registry()
from kivi.tools.video import MediaVideoTool

registry.register(MediaVideoTool())
```

- Имя — `media.video`; риск `R1`; capability `media.generate`; аудит-действие
  `tool.media.video`.
- `dry_run` показывает URL кадра, размеры, длительность, шаблон выхода и
  предупреждения, ничего не создавая; executor помечает такой вызов как
  `dry run`.
- Артефакт — один путь к MP4; передавайте его дальше как `untrusted:web`.
- CLI: `kivi media video "<prompt>" --width 512 --height 512 --duration 4
  --model flux [--seed 42]`. Флаги совпадают с полями `VideoGenerateArgs`,
  поэтому CLI ничего не добавляет и не обходит валидацию.
- Политика `media.generate` уже выдаётся там, где разрешены `media.image` и
  `media.sdxl`; отдельных grant'ов не требуется.
- Тест реестра (`tests/unit/test_tools.py`) проверяет наличие `media.video` в
  `registry.names()`.

## 13. Будущий настоящий видео-провайдер

Когда появится доступный официальный API (Wan/LTX через HF Spaces,
Runway/Pika/Luma/Kling — по факту доступности и ToS), срез должен выглядеть
иначе:

- асинхронный цикл **submit → poll → download → artifact** вместо одного
  длинного HTTP-запроса; job-очередь, прогресс и отмена;
- жёсткие лимиты длительности, разрешения и размера; учёт watermark и кредитов;
- тот же фиксированный-host/denylist/zone-подход и `untrusted:web`;
- бюджет и явное разрешение через Cloud Broker, если провайдер платный;
- запрет авто-регистрации, обхода CAPTCHA, мультиаккаунтинга и нарушения ToS;
- локальный fallback (`media.video`) остаётся безопасным дефолтом, когда
  внешний провайдер недоступен или не разрешён.

До этого `media.video` — единственный видео-инструмент, и он честно называется
fallback'ом.

## 14. Типичные ошибки

| Симптом | Причина и что делать |
|---|---|
| `ffmpeg binary not found …` | Нет пакета/бинарника: `pip install imageio-ffmpeg`; проверьте `imageio_ffmpeg.get_ffmpeg_exe()`. |
| `ffmpeg failed with exit code N: …` | Кодирование не удалось; в тексте — tail stderr. Повтор без изменения параметров вряд ли поможет. |
| `ffmpeg output is not an MP4 file (missing ftyp box)` | Бинарник/runner вернул не MP4; файл удалён. |
| `video is too large (limit 41943040 bytes)` | Слишком большой результат; уменьшите длительность/размер или проверьте runner. |
| `image is too large` | Кадр больше 10 МБ; провайдер вернул слишком большой файл. |
| `HTTP 429` / `HTTP 5xx` | Лимиты/недоступность бесплатного Pollinations; повторите позже, без параллельного шквала запросов. |
| `prompt is blocked by media policy` | Сработал denylist; переформулируйте промпт. |
| `redirects are not followed` | Сервис ответил 3xx; редиректы намеренно запрещены. |
| `denied: …` / `confirmation required` | Нет capability `media.generate` или политика требует approve для R1. |
