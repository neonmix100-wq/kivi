# Kivi Shell: полноэкранная замена Explorer

Версия: 0.1 (09.11.2026).
Связанные документы: `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/ROADMAP.md`.

---

## 1. Цель

Kivi Shell — полноэкранная оболочка поверх Windows, которая заменяет рабочий стол, панель задач,
меню «Пуск», файловый менеджер и поиск, но **не ломает привычные функции Windows**.

Требование пользователя:

> Полноэкранная замена Explorer с доступом ко всем функциям Explorer, чтобы ПК оставался
> полностью рабочим.

Это не «настоящая ОС» и не замена ядра Windows. Это альтернативная оболочка (custom shell),
которая использует Windows API и оставляет `explorer.exe` как аварийный вариант.

---

## 2. Честная оценка

«Все функции Explorer» — это большой объём:

- рабочий стол, иконки, контекстное меню, drag-and-drop;
- панель задач, трей, часы, уведомления, «Показать рабочий стол»;
- меню «Пуск», поиск, закреплённые приложения, недавние;
- файловый менеджер: навигация, вкладки, адресная строка, поиск, сортировка, группы,
  представления, preview, свойства, права, копирование/перемещение/удаление, корзина, undo;
- сетевые пути, съёмные диски, OneDrive, библиотеки, известные папки;
- контекстные меню сторонних программ (7-Zip, Git, антивирус);
- сочетания клавиш, Alt-Tab, Win+E, Win+R, Win+X, Win+S, виртуальные рабочие столы;
- multi-monitor, DPI, доступность, локализация;
- уведомления, фокус-ассистент, быстрые настройки, звук, сеть, Bluetooth, питание.

Поэтому проект идёт **стадиями**:

| Стадия | Что это | Explorer |
|---|---|---|
| A. Full-screen app | Kivi Shell как полноэкранное приложение/лаунчер | Работает как обычно |
| B. Custom shell (beta) | Kivi Shell запускается вместо оболочки, Explorer — fallback | Доступен по горячей клавише |
| C. Default shell | Kivi Shell по умолчанию после soak-тестов | Аварийный fallback |

Пользователь получает полноэкранную замену на стадии C. До этого ПК остаётся полностью рабочим,
потому что Explorer не отключён.

**Важно:** полный паритет с Explorer — не 12–17 дней. M8 даёт P0/P1-функции и fallback;
P2-функции (редкие расширения, виртуальные столы, некоторые системные панели) — v1.x.
Это не отказ от цели, а способ не остаться без рабочего стола.

## 3. Матрица паритета

Приоритеты:

- **P0** — без этого нельзя пользоваться ПК;
- **P1** — ежедневные функции;
- **P2** — редкие/сложные, можно открыть в Explorer.

| Функция | Приоритет | Реализация |
|---|---|---|
| Рабочий стол: обои, иконки, выделение, drag-drop | P0 | Win32 + `IShellFolder` |
| Контекстное меню рабочего стола | P0 | `IContextMenu` + fallback |
| Панель задач: запущенные окна, закреплённые, трей, часы | P0 | `RegisterShellHookWindow`, `Shell_NotifyIcon`, AppBar |
| Меню «Пуск»: приложения, поиск, питание | P0 | `Shell:AppsFolder`, `IApplicationActivationManager` |
| Файловый менеджер: навигация, вкладки, адресная строка | P0 | `IShellFolder`, `IFileOperation` |
| Копирование/перемещение/удаление/переименование | P0 | `IFileOperation` (корзина, undo, конфликты) |
| Поиск по файлам | P0 | Windows Search API / собственный индекс |
| Свойства файла, права, размер, дата | P1 | `IShellFolder2`, property system |
| Preview pane, thumbnails, значки | P1 | `IThumbnailProvider`, `SHGetFileInfo` |
| Сортировка, группировка, представления | P1 | `IShellFolder` + view model |
| Сетевые пути, съёмные диски, OneDrive | P1 | shell namespace |
| Корзина, восстановление, undo | P1 | `IFileOperation` + `SHQueryRecycleBin` |
| Архивы zip | P1 | Windows zip API / libarchive |
| Сторонние контекстные меню | P2 | host `IContextMenu` в отдельном процессе или fallback |
| Alt-Tab / Win+Tab | P1 | свой switcher + `IVirtualDesktopManager` (осторожно) |
| Виртуальные рабочие столы | P2 | Windows API; при нестабильности — fallback |
| Быстрые настройки: звук, сеть, Bluetooth, питание | P1 | Windows API + Settings deep links |
| Уведомления, action center | P1 | Windows toast API |
| Multi-monitor, DPI, разные обои | P0 | per-monitor DPI, `IDesktopWallpaper` |
| Доступность: клавиатура, screen reader, контраст | P1 | UI Automation, ARIA, high contrast |
| Локализация RU/EN | P1 | i18n |
| File associations / «Открыть с помощью» | P1 | shell API + Settings deep link |
| Shell extensions (7-Zip, Git, antivirus) | P2 | curated host или «Открыть в Explorer» |
| Touch/pen/жесты | P2 | указатели, тесты |
| Windows Hello / lock screen | P2 | не заменяем: системный |

## 4. Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│ Kivi Shell UI (Tauri + React + TypeScript)                  │
│ desktop · taskbar · start · files · search · settings       │
│ avatar (three.js) · notifications · command palette         │
└───────────────────────────┬─────────────────────────────────┘
                            │ IPC (typed, local)
┌───────────────────────────▼─────────────────────────────────┐
│ Kivi Shell Service (Rust, обычные права)                    │
│ shell namespace · file ops · index · tray · hotkeys         │
│ window tracking · toast · policy client · crash watchdog    │
└───────────────────────────┬─────────────────────────────────┘
                            │ Windows API / COM
┌───────────────────────────▼─────────────────────────────────┐
│ Windows: IShellFolder, IFileOperation, Shell APIs, Win32    │
└─────────────────────────────────────────────────────────────┘
```

Почему Tauri:

- лёгкий WebView2 вместо Electron;
- Rust для Win32/COM;
- three.js для аватара;
- быстрый старт, меньше RAM/VRAM, чем Electron;
- единый UI для Windows и будущего Linux.

Почему не переписывать файловые операции:

- `IFileOperation` даёт корзину, undo, прогресс, конфликты, права, длинные пути;
- свои реализации легко теряют данные;
- Windows Shell API — единственный способ сохранить совместимость.

## 5. Файловый менеджер

### 5.1. Навигация

- Дерево: Quick Access, This PC, диски, сеть, корзина, OneDrive, библиотеки.
- Вкладки, back/forward/up, breadcrumb, editable address bar.
- История, избранное, недавние.
- Поддержка UNC, длинных путей, junction/symlink (осторожно).
- Drag-and-drop между панелями и из других приложений.

### 5.2. Операции

- Копирование/перемещение/удаление/переименование — только через `IFileOperation`.
- Удаление — в корзину по умолчанию; permanent delete — подтверждение.
- Конфликты — диалог Windows или свой с теми же опциями.
- Undo — через `IFileOperation`/`IUndoManager`, где возможно.
- Прогресс и отмена.
- Проверка прав и защищённых зон перед операцией.
- Никаких «тихих» удалений и обходов политики.

### 5.3. Отображение

- Иконки, список, детали, плитка, thumbnails.
- Сортировка/группировка, фильтры, скрытые/системные файлы.
- Preview pane: текст, картинки, PDF (без выполнения макросов).
- Свойства: размер, даты, владелец, права, атрибуты, хеш (по запросу).
- Быстрый просмотр — только чтение, без автозапуска.

### 5.4. Поиск

- Windows Search API (если индекс включён) или собственный индекс.
- Собственный индекс: USN journal + SQLite FTS5; не читать всё каждый раз.
- Фильтры: тип, дата, размер, путь, содержимое.
- Поиск не должен отправлять содержимое в облако без политики.
- Результаты показывают источник и путь; открытие — по клику.

### 5.5. Контекстные меню

Два режима:

1. **Свой** — для частых действий (открыть, копировать, удалить, свойства, поделиться).
2. **Системный** — host `IContextMenu` для совместимости.

Безопасность:

- не загружать произвольные shell extensions в процесс Kivi;
- использовать отдельный процесс-хост с ограничениями;
- при ошибке/зависании — «Открыть в Explorer»;
- подписанные/проверенные расширения — allowlist;
- никаких автозапусков из меню.

## 6. Рабочий стол и панель задач

### 6.1. Рабочий стол

- Обои, несколько мониторов, разные обои.
- Иконки: This PC, Recycle Bin, пользовательские папки, файлы.
- Сетка, выравнивание, сортировка.
- Контекстное меню: создать, обновить, параметры экрана, персонализация.
- Drag-drop файлов.
- Двойной клик — открыть в Kivi Files или ассоциированном приложении.

### 6.2. Панель задач

- Закреплённые и запущенные приложения.
- Индикаторы, группировка, контекстные меню.
- Трей: `Shell_NotifyIcon`, скрытые иконки.
- Часы/календарь, уведомления.
- «Показать рабочий стол», переключение окон.
- AppBar: резервирование места, автоскрытие.
- Настройка положения/размера, multi-monitor.

### 6.3. Меню «Пуск»

- Поиск приложений и файлов.
- Закреплённые, недавние, все приложения.
- Питание: lock, sign out, restart, shutdown (через политику).
- Быстрые настройки.
- Клавиатурная навигация.

### 6.4. Горячие клавиши

- Win, Win+S, Win+E, Win+R, Win+X — через `RegisterHotKey`/shell hooks.
- Alt-Tab — свой switcher, если Explorer не обрабатывает.
- Win+Tab — виртуальные столы (P2).
- Win+D — показать рабочий стол.
- Win+L — оставить системному Windows.
- Ctrl+Shift+Esc — Task Manager (системный).
- Аварийная комбинация: `Ctrl+Alt+Shift+E` — вернуть Explorer.

Некоторые сочетания зарезервированы Windows; их нельзя перехватить без низкоуровневых хуков.
Для таких — документированный fallback.

## 7. Аватар в Shell

- Аватар — отдельное прозрачное always-on-top окно или слой внутри Shell.
- Состояния: `idle`, `listening`, `thinking`, `speaking`, `happy`, `error`, `sleep`.
- Липсинк по амплитуде TTS; позже — виземы.
- Скрытие по команде: «Kivi, скройся»; иконка в трее для возврата.
- Второй монитор: перенос окна, запоминание позиции.
- Пауза рендера, когда скрыт/не виден.
- Бюджет: 100–300 МБ VRAM; не блокирует LLM.

## 8. Производительность

| Метрика | Цель |
|---|---|
| Холодный старт Shell | < 2 с |
| Открытие папки (локально) | < 150 мс для 1000 объектов |
| Поиск | < 300 мс для типового запроса |
| Память UI | < 300 МБ |
| Память service | < 150 МБ |
| VRAM аватара | 100–300 МБ |
| FPS аватара | 30 idle / 60 speaking |
| Shell не должен грузить CPU в idle | < 2% |

Приёмы:

- виртуализация списков;
- ленивая загрузка иконок/thumbnails;
- кэш иконок и метаданных;
- отдельный процесс для тяжёлых операций;
- debounce поиска;
- не сканировать диск целиком;
- пауза анимаций при скрытии.

## 9. Безопасность

- Shell — обычные права; admin-операции — elevated broker.
- Все файловые операции проходят через Policy Engine (Protected Zones, подтверждения).
- Shell extensions — отдельный процесс, allowlist, fallback.
- Никаких автозапусков скачанных файлов.
- Ссылки и ярлыки показывают цель; `javascript:`/`data:` блокируются.
- Уведомления не содержат секретов.
- Поисковый индекс не индексирует Protected Zones и секреты.
- Буфер обмена: не логировать содержимое; очистка по запросу.
- Скриншоты/превью — только чтение, без сетевой отправки.
- Аудит: запуск, файловые операции, смена оболочки, ошибки.
- Kill switch и fallback Explorer.

---

## 10. Fail-safe и восстановление

Обязательные механизмы:

1. **Explorer не удаляем.** `explorer.exe` остаётся в системе.
2. **Аварийная комбинация** `Ctrl+Alt+Shift+E` запускает Explorer и возвращает стандартную оболочку.
3. **Watchdog:** если Shell не отвечает 5 с — предложить перезапуск/Explorer.
4. **Safe mode:** при падении Shell при входе — автоматический Explorer.
5. **Переключатель режимов:** A/B/C в настройках.
6. **Откат:** перед сменой shell — точка восстановления и бэкап реестра.
7. **Логи:** причина падения, последние действия.
8. **Никаких «тихих» изменений реестра:** только через elevated broker с подтверждением.

Смена shell (стадия B/C):

- выполняется через elevated broker;
- пользователь подтверждает;
- создаётся точка восстановления;
- Shell проверяется healthcheck;
- при ошибке — автоматический откат на Explorer;
- изменения логируются.

## 11. Тестирование

### 11.1. Функциональные тесты

- 100+ файловых операций: копирование, перемещение, удаление, конфликты, права, длинные пути.
- 20+ сценариев рабочего стола.
- 20+ сценариев панели задач/трея.
- 20+ сценариев меню «Пуск»/поиска.
- Multi-monitor, DPI 100/125/150/200%, разные разрешения.
- Сетевые пути, съёмные диски, OneDrive.
- Контекстные меню популярных программ.
- Горячие клавиши и Alt-Tab.
- Доступность: клавиатура, screen reader, контраст.
- Аварийный возврат Explorer.

### 11.2. Нефункциональные тесты

- 7-дневный soak.
- Утечки памяти/хендлов.
- Нагрузка: 10 000 файлов в папке.
- Поиск на 1 млн файлов.
- Падение Shell и восстановление.
- Обновление Shell без потери данных.
- Безопасность: path traversal, shell extension, malicious LNK.

### 11.3. Критерии приёмки M8

- P0/P1-функции работают без Explorer.
- Аварийный возврат Explorer < 5 с.
- 7 дней без деградации.
- Нет потери данных при файловых операциях.
- Нет зависаний при 10 000 файлов.
- Все операции в аудите.
- Пользователь может вернуться к Explorer одной комбинацией.

## 14. Решения, которые нужны от пользователя

1. **Режим запуска:** A (приложение) → B (beta-замена) → C (по умолчанию) — ок?
2. **Explorer fallback:** оставить `Ctrl+Alt+Shift+E` и автоматический возврат — ок?
3. **Внешний вид:** тёмная тема, стиль Kivi, где аватар (справа/слева/по центру)?
4. **Панель задач:** снизу как в Windows или своя (сверху/сбоку)?
5. **Меню «Пуск»:** полноэкранное или компактное?
6. **Виртуальные столы:** нужны сразу или P2?
7. **Сторонние контекстные меню:** нужны 7-Zip/Git или достаточно «Открыть в Explorer»?
8. **Автозапуск Shell:** при входе или по горячей клавише?

## 15. Итог

Kivi Shell может заменить Explorer, но безопасный путь — **постепенно**:

- сначала полноэкранное приложение, где Explorer жив;
- затем beta-замена с аварийным возвратом;
- затем default shell после 7-дневного soak.

Это сохраняет главное требование: **ПК остаётся полностью рабочим**, даже если Shell упадёт.
