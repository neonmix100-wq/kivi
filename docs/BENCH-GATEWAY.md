# Benchmark: переключение моделей Gateway

Дата: 2026-11-10. Машина: Windows 11, NVIDIA GPU с 8192 МБ VRAM (NVML),
Ollama на `127.0.0.1:11434`. Модели измерены на этой машине:
`qwen3.5:4b` (router, ~3800 МБ), `qwen2.5-coder:7b` (code, ~4700 МБ при 8K),
`bge-m3` (embedding, 0 МБ VRAM — считается на CPU). Рабочий стол занимает ~3.1 ГБ VRAM.

## Команда

```powershell
.venv\Scripts\python.exe scripts\bench_gateway.py `
  --switches 20 --models qwen3.5:4b,qwen2.5-coder:7b,bge-m3 `
  --timeout 600 --margin-mb 256
```

Цикл приёмки: **chat → code → embedding → chat**. Каждое переключение:
`acquire`/`embed` → замер свободной VRAM → `release` → ожидание фактического
возврата памяти. Тяжёлые модели не помещаются вместе, поэтому каждое
переключение — это eviction предыдущей.

Перед запуском контекст модели фиксируется по registry (`num_ctx=4096/8192`)
через `options` при загрузке. Без этого Ollama брала дефолт модели (до 262144),
раздувала модель до 14 ГБ и уходила в CPU/swap.

## Результат

| Метрика | Значение |
|---|---:|
| Переключений | 20 |
| Успешно | 20 |
| Ошибок / OOM | 0 |
| Loads / unloads / evictions | 20 / 20 / 20 |
| Минимум свободной VRAM при загрузке | 2034 МБ |
| Минимум свободной VRAM после release | 7089 МБ |
| Максимальное время загрузки | 3156 мс |
| Типичное время загрузки (тёплый кэш) | 2–3 с |

Полный отчёт: `data/bench/gateway-20261110-021819.json` (не коммитится).

## Что показал первый прогон

Первый прогон без `num_ctx` прошёл 20/20, но свободная VRAM падала до 26 МБ:
Ollama грузила модель с контекстом 262144 и частично вытесняла её в CPU.
Второй прогон с контекстом 4096/8192 и margin 512 дал 10 отказов из 20:
`qwen2.5-coder:7b` требовал 4800 + 512 МБ, а фактически помещается в ~4.7 ГБ.
После измерения реального footprint'а и снижения margin до 256 МБ все
20 переключений проходят с запасом 448 МБ.

## Выводы

1. **Приёмка «20 переключений без OOM» пройдена** на полном цикле
   chat → code → embedding → chat.
2. После `release` VRAM возвращается: минимум 7089 МБ свободно. Сразу после
   ответа память освобождается не мгновенно — benchmark ждёт до 10 с.
3. Контекст нужно фиксировать при загрузке: `ModelSpec.context` → `num_ctx`.
   Иначе локальная модель может занять в 3–4 раза больше VRAM, чем ожидается.
4. Safety margin 512 МБ слишком консервативен для 8 ГБ карты с рабочим столом
   на 3.1 ГБ; 256 МБ даёт фактический запас и пропускает 7B-модель.
5. Embedding-модель `bge-m3` не тратит VRAM (CPU), но её загрузка/выгрузка
   тоже проходит через lease manager. Эндпоинт — `/api/embed`, не `/api/generate`.
