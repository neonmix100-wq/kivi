# Benchmark: переключение моделей Gateway

Дата: 2026-11-10. Машина: Windows 11, NVIDIA GPU с 8192 МБ VRAM (по `nvidia-smi`),
Ollama на `127.0.0.1:11434`. Модели: `qwen3.5:4b` (router, 3300 МБ) и
`qwen2.5-coder:7b` (code, 4800 МБ).

## Команда

```powershell
.venv\Scripts\python.exe scripts\bench_gateway.py `
  --switches 20 --models qwen3.5:4b,qwen2.5-coder:7b --timeout 600
```

Каждое переключение: `acquire` → замер свободной VRAM → `release`. Обе модели
не помещаются вместе, поэтому каждое переключение — это eviction предыдущей.

## Результат

| Метрика | Значение |
|---|---:|
| Переключений | 20 |
| Успешно | 20 |
| Ошибок / OOM | 0 |
| Loads / unloads / evictions | 20 / 20 / 20 |
| Минимум свободной VRAM при загрузке | 26 МБ |
| Минимум свободной VRAM после release | 5888 МБ |
| Максимальное время загрузки | 27 078 мс |
| Медиана времени загрузки (примерно) | 11–12 с |

Полный отчёт: `data/bench/gateway-20261110-001314.json` (не коммитится).

## Выводы

1. **Приёмка «20 переключений без OOM» пройдена** для пары chat/code.
2. После `release` VRAM возвращается: 5888–5917 МБ свободно, то есть модель
   действительно выгружается, а не остаётся в резидентной памяти.
3. **Свободная VRAM при загрузке падала до 26 МБ.** Проверка бюджета идёт
   *до* загрузки; пока Ollama грузит веса, рабочий стол и браузер могут занять
   ещё несколько сотен МБ. Safety margin 512 МБ не гарантирует запас в худшем
   случае.
4. Время загрузки нестабильно: 5–27 с, зависит от состояния page cache и
   фоновой нагрузки. Для UX нужен стриминг и индикатор «загружаю модель».

## Что делать дальше

- Добавить post-load проверку давления и адаптивный safety margin.
- Установить `bge-m3` и повторить цикл «chat → code → embedding → chat».
- Перейти с `nvidia-smi` на NVML для более дешёвого и точного мониторинга.
- Добавить fallback при искусственном OOM (следующий unchecked пункт этапа 2).
