# Дорожная карта Jarvis

Версия: 0.1. Оценки — для одного разработчика с ИИ-помощником, 10–15 часов в неделю.
Полный v1 — ориентировочно **3–5 месяцев**; первый полезный текстовый Jarvis — **4–6 недель**.

---

## 1. Принципы поэтапности

1. Каждый этап заканчивается **работающим вертикальным срезом**, а не набором модулей.
2. Сначала — текст и инструменты, потом голос, потом медиа.
3. Модели подключаются через Gateway с первого дня; никаких прямых вызовов Ollama из кода.
4. Права и аудит — не «потом», а вместе с первым инструментом.
5. После каждого milestone — демо-сценарий и замер ресурсов.

- [ ] Первый коммит документации.

**Приёмка:** есть `docs/BASELINE.md` с цифрами; решения зафиксированы; репозиторий собирается.

## 4. Этап 1 — скелет ядра (3–5 дней)

**Цель:** запускаемый каркас, в который можно вставлять модули.

Задачи:

- [ ] `src/jarvis` с пакетами `kernel/brain/models/senses/tools/memory/interfaces/safety`.
- [ ] Загрузка `config/*.yaml` с валидацией Pydantic.
- [ ] Структурные логи (JSONL) + консоль.
- [ ] SQLite + миграции (минимум: `tasks`, `steps`, `events`, `audit`).
- [ ] Event Bus (asyncio) + `trace_id`.
- [ ] CLI: `jarvis doctor`, `jarvis models`, `jarvis chat` (заглушка).
- [ ] `jarvis doctor`: GPU, RAM, диск, Ollama, WebUI, модели, версии.
- [ ] Unit-тесты на конфиг и БД.

**Приёмка:** `jarvis doctor` показывает железо и бэкенды; событие `task.created` пишется в БД и лог; тесты зелёные.

## 5. Этап 2 — Model Gateway (5–7 дней)

**Цель:** управляемое послойное использование GPU без OOM.

Задачи:

- [ ] Registry моделей из `config/models.yaml` + измеренные footprint'ы.
- [ ] Адаптер Ollama: загрузка, `keep_alive`, выгрузка, стриминг.
- [ ] NVML-монитор: total/used/free/shared, процессы.
- [ ] Lease Manager: приоритеты, TTL, эксклюзивность, очередь.
- [ ] Eviction: LRU + фон + размер; проверка фактического освобождения.
- [ ] Fallback: уменьшить контекст → частичный offload → CPU → облако (если разрешено).
- [ ] Watchdog на зависшие загрузки/выгрузки.
- [ ] Benchmark-скрипт: 20 переключений, замер peak VRAM, токенов/с.
- [ ] Метрики в `model_runs`.

**Приёмка:**

- 20 циклов «чат → кодер → эмбеддинги → чат» без OOM.
- После простоя 10 мин VRAM = 0 (или только разрешённый tier 0).
- Искусственный OOM приводит к понятному fallback, а не к падению.
- В отчёте — реальные цифры, а не эвристики.

---

## 6. Этап 3 — инструменты, права, аудит (5–7 дней)

**Цель:** агент умеет безопасно действовать.

Задачи:

- [ ] Контракт `Tool`, реестр, JSON-схемы, `dry_run`.
- [ ] Permission Engine: capabilities, scope, TTL, режимы allow/confirm/deny.
- [ ] Инструменты: `fs.list/read/search/write/delete`, `shell.exec`, `proc.*`, `clipboard`, `screen.capture`, `http.get`.
- [ ] Санитайзер путей (no traversal, no симлинки за пределы workspace).
- [ ] Запуск процессов без shell-склейки, таймауты, убийство process tree.
- [ ] Подтверждения в CLI: точное действие, риск, область.
- [ ] Аудит всех вызовов и отказов.
- [ ] 30+ тестов, включая попытки обхода прав.

**Приёмка:**

- Запись вне workspace невозможна без явного grant.
- `format`, `diskpart`, `reg delete`, `shutdown` блокируются.
- Каждое действие имеет запись в аудите.
- Обход через `..`, симлинк, PowerShell-инъекцию не проходит.

## 7. Этап 4 — память и контекст (4–6 дней)

**Цель:** Jarvis помнит и находит нужное.

Задачи:

- [ ] Схема SQLite: messages, facts, artifacts, preferences.
- [ ] Артефакты: content-addressed хранение.
- [ ] LanceDB + bge-m3 на CPU; чанкинг и метаданные.
- [ ] Гибридный поиск: FTS5 + вектор + свежесть.
- [ ] Профиль пользователя (YAML) и правил.
- [ ] Context Builder с бюджетом токенов и суммаризацией.
- [ ] Импорт `D:\AI-base` (read-only, с исключениями).
- [ ] Команды `jarvis memory search/forget/export`.

**Приёмка:**

- 10 фактов из диалога находятся после перезапуска.
- 20 тестовых запросов к базе знаний дают релевантные источники.
- «Забудь X» реально удаляет запись и векторы.
- Секреты не попадают в индекс.

## 8. Этап 5 — агентный цикл, M1 (5–7 дней)

**Цель:** первый полноценный текстовый Jarvis.

Задачи:

- [ ] Intent Router: fast path / deep path.
- [ ] Planner: DAG, JSON-схема, лимиты шагов и времени.
- [ ] Validator: схемы, циклы, права, ресурсы.
- [ ] Executor: топологический порядок, параллелизм, чекпоинты, отмена.
- [ ] Verifier: детерминированные проверки + LLM-судья.
- [ ] Replan (до 2 раз) и честный отчёт при провале.
- [ ] Reflector: факты и итог в память.
- [ ] Стриминг прогресса в CLI.
- [ ] 20 сценарных тестов.

**M1 — демо:**

> «Джарвис, найди в D:\Docs договор с ООО Ромашка, сделай выжимку, создай в workspace скрипт для проверки суммы и запусти его».

**Приёмка:**

- 80% из 20 сценариев проходят без вмешательства.
- Ни одного действия без аудита.
- При провале шага — понятная причина и след.
- p50 простой команды < 3 с, deep path < 30 с (без учёта модели).

---

## 9. Этап 6 — голос, M2 (5–7 дней)

**Цель:** «Джарвис» слышит и отвечает.

Задачи:

- [ ] Захват микрофона и loopback (перенос из `ai-agent`).
- [ ] Wake word openWakeWord «Джарвис» + push-to-talk.
- [ ] Silero VAD + streaming STT (faster-whisper).
- [ ] Piper TTS, русский голос, потоковая озвучка.
- [ ] Barge-in: «стоп» прерывает речь и задачу.
- [ ] Подтверждения голосом («подтверждаю»/«отмена»).
- [ ] Пауза микрофона, индикатор в трее, горячая клавиша.
- [ ] Метрики: false wake, WER на 30 фразах, latency.

**Приёмка:**

- Пробуждение < 1,5 с; простая голосовая команда < 3 с.
- Ложные пробуждения < 1/час в тишине.
- «Джарвис, стоп» останавливает TTS и задачу.
- Голосовой сценарий M1 повторяется без клавиатуры.

## 10. Этап 7 — код и песочница, M3 (7–10 дней)

**Цель:** агент пишет и проверяет код, не ломая систему.

Задачи:

- [ ] `code.run` в WSL2 `jarvis-sandbox` или Windows Sandbox.
- [ ] Монтирование только workspace, сеть off по умолчанию, лимиты.
- [ ] Индексация репозитория, чтение файлов, патчи.
- [ ] Git: ветка на задачу, diff, commit только с подтверждением.
- [ ] Цикл: сгенерировал → запустил тесты → исправил (до 2 раз).
- [ ] Запуск линтера/тестов проекта.
- [ ] Отчёт: что изменено, какие тесты прошли, риски.

**Приёмка:**

- Небольшой проект (CLI-утилита + тесты) создаётся и проходит тесты.
- Код не пишет вне workspace.
- Установка пакетов — только с подтверждением.
- При падении тестов агент исправляет или объясняет, а не зацикливается.

---

## 11. Этап 8 — медиа, M4 (7–10 дней)

**Цель:** картинки локально, видео — экспериментально/облако.

Задачи:

- [ ] Адаптер ComfyUI (workflow JSON) + fallback на SD WebUI.
- [ ] SDXL txt2img, img2img, upscale; очередь и выгрузка после job.
- [ ] Проверка бюджета: выгрузить LLM перед SDXL.
- [ ] Галерея артефактов и метаданные (prompt, seed, model).
- [ ] Видео: Wan 2.1 1.3B / LTX-Video 2B, 480p, 2–5 с; либо облачный API.
- [ ] Ограничитель: не запускать видео, если бюджет < нужного.
- [ ] Замер: время, peak VRAM, температура.

**Приёмка:**

- 1024×1024 SDXL < 60 с, без OOM.
- Во время генерации LLM выгружена, после — доступна.
- Видео 480p/3 с работает локально **или** документирован облачный fallback.
- Все артефакты находятся и открываются из UI.

## 12. Этап 9 — браузер и ОС, M5 (5–7 дней)

Задачи:

- [ ] Playwright/CDP: открыть, прочитать, кликнуть, заполнить, скачать.
- [ ] Изоляция: отдельный профиль или управляемая вкладка.
- [ ] UI Automation: окна, фокус, клики, клавиатура (R2, подтверждение).
- [ ] Захват экрана + OCR + VLM для разбора интерфейса.
- [ ] Сценарии: поиск, форма, бронирование (без оплаты), сбор данных.
- [ ] Защита от prompt injection со страниц.

**Приёмка:**

- 10 браузерных сценариев проходят.
- 5 UI-сценариев (открыть приложение, найти окно, нажать) проходят.
- Опасные клики (удалить, оплатить) требуют подтверждения.
- Страница не может заставить агента выполнить действие.

- Автозапуск и восстановление после перезагрузки работают.

## 15. Этап 12 — развитие

- Telegram/почта/календарь (с allowlist и шифрованием).
- MCP-сервер для интеграции с другими агентами.

- Самосовершенствование: предложить изменение → ветка → тесты → подтверждение.
- Мобильный клиент через защищённый туннель.

## 18. Definition of Done для каждого этапа

- Код в репозитории, проходит линтер и тесты.
- Есть демо-сценарий, который можно повторить.
- Обновлены `README`/`ARCHITECTURE`/ADR.
- Замерены ресурсы и латентность.
- Нет известных критичных проблем безопасности.
- Следующий этап не начинается, пока приёмка не выполнена.
