Сильные стороны:

- рабочая связка **faster-whisper (CUDA) + Ollama + голосовые команды**;
- реестр инструментов и режимов (`@tool`, `@register_mode`);
- web-UI, отдаваемый локально, с токеном и проверкой источника;
- безопасная работа с терминалом (команды вводит только человек, у LLM нет доступа к shell);
- тесты логики, e2e-заготовки, обработка CUDA-библиотек, single-instance, elevate;
- практический опыт: русская речь, пробуждение по слову «Агент», подтверждения, журналирование.

## D:\workspace — что взять

Что полезно:

- `models_config.json`: маппинг «тип задачи → модель → num_gpu»;
- `vram_manager.py`: `pynvml`, `keep_alive: 0`, ожидание освобождения VRAM;
- `router.py`: FastAPI-эндпоинт, переключение моделей, прокси в SD WebUI;
- `test_vram_switching.py`: идея теста переключения.

Что переписать:

- `predict_model_size()` — заглушка (200/400/800 МБ по имени), а не реальный замер;
- глобальная переменная `current_model` без блокировок и очереди;
- нет leases, приоритетов, watchdog, обработки OOM, частичного offload;
- сервер слушает `0.0.0.0` — для локального ассистента это риск;
- нет проверки, что VRAM действительно освободилась (только таймаут);
- модель и изображение не согласованы по бюджету.

Вывод: **концепция «одна модель за раз» правильная, реализация — прототип.** В новом проекте будет Model Gateway с измеримыми footprint'ами.
